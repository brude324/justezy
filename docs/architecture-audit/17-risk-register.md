# Section Q: Architectural Risk Register

## 1. Technical Risk Evaluation

This register lists all identified architectural risks ranked strictly by **technical severity and impact on the SaaS migration**.

| Rank | Risk Title | Evidence in Codebase | Technical Impact | Likelihood | Migration Consequence | Suggested Mitigation |
| :---: | :--- | :--- | :---: | :---: | :--- | :--- |
| **1** | **Server Action Authorization Bypass** | [src/lib/actions.ts](file:///c:/Users/Abhijeet%20Rawat/Desktop/justezy/src/lib/actions.ts) (Commented-out and missing auth checks across all mutation actions) | **CRITICAL** | **HIGH** | Malicious or unauthorized users can perform arbitrary CRUD on any entity in the database. | Implement strict higher-order action guard (`withAuth(permission, handler)`) validating DB roles and tenant context before execution. |
| **2** | **Catastrophic Accidental Deletions via `FormModal` Mapping** | [src/components/FormModal.tsx#L24-L32](file:///c:/Users/Abhijeet%20Rawat/Desktop/justezy/src/components/FormModal.tsx#L24-L32) (`deleteActionMap` points 7 models to `deleteSubject`) | **CRITICAL** | **HIGH** | Deleting an announcement, attendance, or event deletes academic subjects with the same numeric ID. | Correct action mappings immediately; decouple delete actions into dedicated typed handlers per entity. |
| **3** | **Absence of Multi-Tenant Scoping (Data Leakage)** | [prisma/schema.prisma](file:///c:/Users/Abhijeet%20Rawat/Desktop/justezy/prisma/schema.prisma) (0 models have `tenantId`) | **CRITICAL** | **HIGH** | Cross-tenant data contamination; any query returns data across all educational institutions. | Introduce `Tenant` table, add `tenant_id` foreign keys to all models, and enforce query scoping via Prisma Client extensions. |
| **4** | **Leaked Live Secrets in Repository** | [/.env.example](file:///c:/Users/Abhijeet%20Rawat/Desktop/justezy/.env.example) (Supabase DB URL, Clerk keys, Cloudinary details hardcoded) | **CRITICAL** | **HIGH** | External actors can access Supabase DB directly, bypass application controls, and exfiltrate data. | Revoke and rotate all leaked credentials immediately; scrub Git history and replace `.env.example` with sanitized placeholders. |
| **5** | **Zero Automated Testing Baseline** | Zero test files, no test runner in `package.json` | **HIGH** | **HIGH** | High probability of regression during core schema refactoring, auth migration, and RBAC implementation. | Stand up Vitest and integration test harness prior to modifying schema or authentication layers. |
| **6** | **Global Unique Constraint Collisions** | `Subject.name`, `Class.name`, `Grade.level` defined with global `@unique` in `schema.prisma` | **HIGH** | **HIGH** | Tenant B cannot create a class named "10A" or subject "Math" if Tenant A already created it. | Refactor unique constraints to composite keys: `@@unique([tenantId, name])`. |
| **7** | **Clerk User Creation Distributed Transaction Failure** | [src/lib/actions.ts#L145-L172](file:///c:/Users/Abhijeet%20Rawat/Desktop/justezy/src/lib/actions.ts#L145-L172) (Calls Clerk API, then Prisma, without 2PC or compensation) | **HIGH** | **MEDIUM** | If PostgreSQL insert fails, an orphaned user remains provisioned in Clerk with no DB linkage. | Decouple Clerk user provisioning; rely on DB-first invitation workflows or transactional outbox pattern. |
| **8** | **Zero Background Processing Capabilities** | No Redis or BullMQ; user creation and data processing executed synchronously | **HIGH** | **HIGH** | Edge timeouts on bulk actions (importing students, sending notifications, report card generation). | Introduce Redis and a dedicated BullMQ worker container for asynchronous workloads. |
| **9** | **Complete Absence of PWA Features** | No service worker, no webmanifest, no offline cache in codebase | **HIGH** | **HIGH** | Fails core requirement of delivering a reliable PWA experience on low-bandwidth mobile devices. | Implement `@serwist/next`, generate Web App Manifest, and build offline timetable/attendance caching. |
| **10** | **Prisma Runtime Crash on Password Updates** | [src/lib/actions.ts#L202](file:///c:/Users/Abhijeet%20Rawat/Desktop/justezy/src/lib/actions.ts#L202) (`updateTeacher` passes `password` to `prisma.teacher.update`) | **MEDIUM** | **HIGH** | Updating a teacher or student with a new password throws a Prisma client error (`Unknown argument 'password'`). | Remove `password` field from Prisma update payload (passwords reside exclusively in Clerk). |
| **11** | **Missing Secondary Database Indexes** | Zero `@@index` declarations on foreign keys (`studentId`, `lessonId`, etc.) | **MEDIUM** | **HIGH** | Sequential table scans on all joined queries, causing database slowdown as row counts grow. | Add composite indexes on `[tenantId, studentId]`, `[tenantId, classId]`, and all foreign key relations. |
| **12** | **Broken Docker Configuration** | [Dockerfile](file:///c:/Users/Abhijeet%20Rawat/Desktop/justezy/Dockerfile) (runs `prisma migrate dev` during image build), [docker-compose.yml](file:///c:/Users/Abhijeet%20Rawat/Desktop/justezy/docker-compose.yml) (service name typo) | **MEDIUM** | **HIGH** | Docker builds and local container startup fail out of the box. | Overhaul `Dockerfile` to multi-stage standalone runner; fix service names in `docker-compose.yml`. |
