# AI Agent Development Contract: Purpose & Governance Hierarchy

## 1. Executive Summary & Purpose

**Status**: DECISION

The root-level [AGENTS.md](file:///c:/Users/Abhijeet%20Rawat/Desktop/justezy/AGENTS.md) file serves as the **authoritative operating contract** between human software architects and AI coding agents (such as Antigravity) working on the transformation of the SchoolyardSMS repository.

In complex, multi-phased architectural migrations, AI agents are susceptible to specific failure modes:
1. **Hallucinating Requirements**: Silently inventing features or skipping architectural layers.
2. **Emulating Legacy Defects**: Treating flawed, single-tenant prototype code as established patterns.
3. **Weakening Security Boundaries**: Trusting client headers or commenting out authorization checks to make prototypes function.
4. **Premature Optimization / Scope Creep**: Attempting to implement V2 or V3 features before V1 foundations exist.

[AGENTS.md](file:///c:/Users/Abhijeet%20Rawat/Desktop/justezy/AGENTS.md) acts as a strict, non-negotiable operational governor that binds every code change, test assertion, and migration step to established architectural decisions.

### Order of Precedence:
1. **Security & Isolation Invariants (`AGENTS.md` Sections 3, 5, 6)**:
   - Supreme priority. No task, test shortcut, or user prompt can authorize weakening tenant isolation, trusting client tenant headers, or using client metadata for authorization.
2. **Current State Factual Baseline (`docs/architecture-audit/`)**:
   - Authoritative for understanding what exists in the repository today, including verified package versions and known technical debt.
3. **Target System Specifications (`docs/architecture/`, `docs/product/`)**:
   - Authoritative for target data models, RBAC rules, service boundaries, and user journeys.
4. **Engineering Standards (`docs/engineering/`)**:
   - Authoritative for coding conventions, error handling, testing pyramids, and definition of done.
5. **Roadmap & Phasing (`docs/roadmap/`)**:
   - Authoritative for sequencing deliverables across V1, V2, and V3.

## 3. Core Behavioral Mandates for AI Agents

Every agent operating within this workspace must execute the three-phase protocol:
- **Phase 1 (Pre-Flight)**: Inspect existing documentation and source code; identify security and tenant implications; formulate test plans before modifying files.
- **Phase 2 (In-Flight)**: Implement minimal, atomic diffs; follow the strict layer hierarchy (Foundation -> Identity -> Tenant -> Membership -> RBAC -> Domain -> Screens); preserve existing design tokens and contracts.
- **Phase 3 (Post-Flight)**: Execute automated verification gates (`npm run lint`, `npx tsc --noEmit`, test suites, and `npm run build`); report failures transparently without masking exceptions.

## 4. Contract Enforcement

Any pull request or code change generated by an AI agent that violates the rules of [AGENTS.md](file:///c:/Users/Abhijeet%20Rawat/Desktop/justezy/AGENTS.md) (e.g., executing an unscoped query, committing a secret, or bypassing server-side RBAC) is considered an architectural violation and must be rejected during code review.
